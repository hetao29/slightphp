# 升级到 SlightPHP 6.2.0

6.2.0 收紧配置、路径、验证码和日志处理规则。已有 6.0 / 6.1 应用应检查以下行为变化；5.x 应用还需先按 [6.0 迁移指南](migration-6.0.md)调整控制器和插件类名。完整更新记录见 [Changelog](../CHANGELOG.md)。

本文记录 6.2.0 的变化。升级到当前 6.3.0 时，还需按 [6.3 迁移指南](migration-6.3.md)修改控制器签名，并检查 6.2.1 / 6.2.2 的数据库变化；下方 `^6.2` 约束也允许安装 6.3，因此不能据此保留旧签名。

## 安装

PHP 和依赖要求保持为 PHP 8.0+、PDO、Redis 扩展、Guzzle 和 Gregwar Captcha；插件的附加运行条件见[插件指南](plugins.md)。将应用的 Composer 约束调整为 `^6.2`：

```bash
composer require hetao29/slightphp:^6.2
```

## 配置文件

Config 不再解析 `.conf` 等旧格式。将配置转换为 JSON 对象或数组，并更新 `Config::getConfig()`、`Db::setConfigFile()`、`Redis::setConfigFile()` 等调用的路径。`.json` 现在必须是严格 JSON；含注释的文件需改用 `.jsonc`。两种格式均不允许尾随逗号。

不再读写或反序列化临时文件缓存，旧 `0SConfig_Cache_*` 文件不再使用。仅保留进程内缓存；修改配置后需重启常驻进程，或保持 `Config::$CACHE = false`。关闭缓存不会清空已有结果。异常类型和返回值见 [Config 说明](plugins.md#config)。

## 请求路径

路径默认最多 10 段，包含区域、page、entry 和路径参数；超过上限时 `run()` 返回 `false`，不加载控制器。正常请求、CLI 和内部调用均受限制。已有路由需要更多路径段时，在初始化阶段按实际需要调整：

```php
SlightPHP::setMaxDepth(15); // 必须大于等于 1
```

未超限的路径参数保持原样，默认区域、页面和入口的补全不额外计数。详情见[核心调度文档](framework.md)。

## 模板与语言文件

模板源文件及编译文件必须分别位于模板目录及编译目录内，语言文件必须位于语言根目录内；检查是否依赖跨目录路径或指向目录外的符号链接。重新生成模板编译缓存，并确认运行用户可写编译目录。新建编译目录默认 `0700`，新建或重新写入的编译文件设为 `0600`；已有目录和命中的缓存文件不会自动修改权限。

模板 `escape` 修饰器现在明确转义单双引号并替换非法 UTF-8。Language 忽略非法语言标签、非法 q 值及 `q=0`，限制请求头为最多 8192 字节、前 32 项；仍按出现顺序查找，不按 q 值排序。自定义 locale 和 zone 的规则见 [Language 说明](plugins.md#language)。

## 验证码

每个会话前缀只保留最新验证码，刷新会替换旧记录；默认有效期为 300 秒，可在生成前设置 `Captcha::$ttl` 为正整数。`check()` 成功后立即移除验证码，同一业务流程只校验一次。生成及校验时需保持活动会话。

旧的“前缀 + 验证码”会话记录不再接受，升级后应提示用户重新获取验证码。不同用途可使用不同前缀隔离。并发一次性校验依赖会话后端的互斥锁配置，详见 [Captcha 说明](plugins.md#captcha)。

## 错误与日志

`Error::$LOGARGS` 默认为 `false`，错误日志和控制台输出不再包含调用栈参数；如需恢复，可显式设为 `true`，但字段名脱敏不能覆盖所有敏感值。错误和异常消息本身的数据不受此开关影响。HTML 错误输出及 Log 的网页控制台注释会转义 HTML；JSON 和纯文本接口应由应用设置正确的 `Content-Type`。

`Log::$LOGTYPE = 'json'` 现在输出 JSON Lines，每条记录包含 `time`、`level` 和始终为参数数组的 `message`。升级日志采集及解析程序，为新格式使用独立日志文件或先轮转旧文件。默认 `text` 模式保留多行文本。格式示例见 [Log 说明](plugins.md#log)。

## 验证

升级后覆盖实际应用的路由、配置加载、模板渲染、语言选择、验证码刷新与重复提交、错误输出及日志采集。仓库示例可运行 `php samples/tests/routing.php` 验证入口、自动加载、模板与 URI 解析；HTTP 验证方法见[部署文档](deployment.md#验证)。
